## Module Map (Signal Flow)
```
clk (100 MHz)
  │
  ├─► input_conditioning
  │     ├─ synchronizer_subsystem → reset, encoder_a, encoder_b, kp, display, arm
  │     └─ debounce_subsystem → step_up, step_down
  │
  ├─► downcounter_subsystem
  │     ├─ control_tick (100 Hz) ──────────────────────► p_controller.sample_tick
  │     └─ pwm_tick (10.06 kHz) ──────────────────────► motor_drive.pwm_tick
  │
  ├─► quad_decoder (encoder_a, encoder_b) ──► position [15:0]
  │
  ├─► setpoint_control (step_up, step_down) ──► setpoint [15:0]
  │
  ├─► p_controller (reference=setpoint, measured=position, kp, sample_tick=control_tick)
  │     └─► command [8:0] (-255..+255)
  │
  ├─► motor_drive (command, arm, pwm_tick)
  │     ├─ motor_en (PWM to L298N ENB)
  │     ├─ motor_in1 (forward → L298N IN3)
  │     └─ motor_in2 (reverse → L298N IN4)
  │
  └─► display_subsystem (position, display_switch)
        ├─ position_to_degrees → display_data (0..2047 or 0..359)
        ├─ bin_to_bcd → 4 BCD digits
        └─ seven_segment_display_subsystem → CA..CG, DP, AN1..AN4
```

## Common Questions by Topic (with Answers)

### **1. Inputs & Timing**
| Question | Answer | Code Reference |
|----------|--------|----------------|
| **Why do encoder signals go through a synchronizer?** | Without it, async encoder edges violate setup/hold on `quad_decoder`'s `ab_previous` → metastability → random position jumps. | `synchronizer_subsystem.sv` lines 13–14 (`ENCODER_A_SYNC`, `ENCODER_B_SYNC`) |
| **Why does the synchronizer have no reset?** | So it *can* synchronize the reset button itself (`RESET_SYNC`). Power-up state flushes in two cycles anyway. | `synchronizer.sv` — no `reset` port, no `if (reset)` in `always_ff` |
| **What is `sample_tick` and where does it come from?** | One-cycle pulse at 100 Hz. Generated by `downcounter_subsystem` → `CONTROL_TICK_GEN` with `PERIOD = CLK_FREQ/CONTROL_FREQ = 1,000,000`. | `downcounter_subsystem.sv` line 4; `downcounter.sv` |
| **Why does the controller only update on `sample_tick`? Why not a second clock?** | Single 100 MHz domain → no CDC, single STA run, simpler timing. `sample_tick` is just a clock enable; all flops use `posedge clk`. | `p_controller.sv` line 25: `if (sample_tick) p_action <= ...` |
| **Why is `control_tick` a clock enable, not a clock?** | Keeps entire design in one clock domain. No multi-clock STA, no CDC, simpler floorplanning. | All modules: `always_ff @(posedge clk)` |

### **2. Quadrature Decoder**
| Question | Answer | Code Reference |
|----------|--------|----------------|
| **Draw A/B waveforms for one line forward. How many counts?** | A leads B by 90°: `00 → 10 → 11 → 01 → 00`. Four edges = **4 counts per line** (x4 decoding). 512 lines/rev → 2048 counts/rev. | `quad_decoder.sv` header + lines 13–14 |
| **What if both A and B change in the same clock cycle?** | Illegal transitions (`00_11`, `10_01`, `11_00`, `01_10`) not in `case` → `default: position <= position` (ignored). Real encoder at 100 MHz can't change both in 10 ns. | `quad_decoder.sv` line 15 (`default`) |
| **What if A and B are swapped on the Pmod?** | Forward/backward ring reverses. `case` items for forward become backward. Fix in hardware: swap motor wires on L298N OUT3/OUT4 — no code change. | `quad_decoder.sv` lines 13–14 |

### **3. Counts Display / Position to Degrees**
| Question | Answer | Code Reference |
|----------|--------|----------------|
| **How does negative position become 0–2047?** | `position_to_degrees.sv` line 10: `count_in_rev = position[10:0]` (low 11 bits). Two's complement: `-512 = 0xFE00`, low 11 bits = `1536` = 270° = -90° mod 360. | `position_to_degrees.sv` line 10 |
| **Why only works because 2048 is a power of two?** | Modulo 2^N = take low N bits. For 500 lines (2000 counts/rev), low bits ≠ modulo. Need divider or `%`, and shift-by-11 no longer divides by 2000. | `disk_pkg.sv`: `COUNTS_PER_REV = 2048`; `position_to_degrees.sv` line 5 |
| **What changes for a 500-line encoder?** | `ENCODER_LINES=500` → `COUNTS_PER_REV=2000`. `REV_BITS=11` but `count_in_rev = position % 2000` (not low bits). Shift-by-11 no longer divides by 2000. | `disk_pkg.sv` line 12; `position_to_degrees.sv` would need divider |
| **Why counts mode 4 digits, degrees mode 3?** | Counts: 0–2047 (4 digits). Degrees: 0–359 (3 digits). `display_subsystem.sv` line 35: `digit_blank = 4'b1000` blanks leftmost in degrees mode → `" 359"` not `"0359"`. | `display_subsystem.sv` line 35 |

### **4. Arithmetic & Data Types (p_controller)**
| Question | Answer | Code Reference |
|----------|--------|----------------|
| **Why is `error` 17 bits when setpoint/position are 16?** | `error = reference - measured`. Max: `32,767 - (-32,768) = 65,535` needs 17 bits. | `p_controller.sv` line 19: `logic signed [IN_WIDTH:0] error` |
| **What does `$signed({1'b0, kp})` do? What breaks without it?** | `kp` is unsigned 4-bit. `{1'b0, kp}` adds sign bit=0 → 5-bit positive signed. `$signed()` forces **signed multiply**. Without: unsigned multiply → negative error wraps to huge positive. | `p_controller.sv` line 20 |
| **Why must product be computed at full width?** | `PRODUCT_WIDTH = 22` (17-bit error + 5-bit kp). Max product: `65,535 × 15 = 983,025` < 2^20. Truncating before multiply → large errors wrap and flip sign. | `p_controller.sv` line 14: `PRODUCT_WIDTH = IN_WIDTH+1 + KP_WIDTH+1` |
| **How does `position_to_degrees` handle negative position?** | Low 11 bits = `position mod 2048` (two's complement). `-512 → 1536 counts = 270°`. Works because `COUNTS_PER_REV = 2048 = 2^11`. | `position_to_degrees.sv` line 10 |

### **5. The Controller**
| Question | Answer | Code Reference |
|----------|--------|----------------|
| **Why are `p_controller` limits parameters, not constants?** | Reuse. Disk: ±255. PI controller (E4): P part unlimited, only sum limited. Boost converter: 0–100%. Same file, different parameters. No `disk_pkg` import → portable. | `p_controller.sv` lines 9–12 |
| **Why does `p_controller` not import `disk_pkg`?** | Zero project-specific constants. All sizes/limits passed as parameters from `disk_top`. | `p_controller.sv` — no `import disk_pkg` |
| **What does `p_action` do between samples?** | Registered output holds last command for 10 ms (100 Hz sample period). | `p_controller.sv` line 25: `if (sample_tick) p_action <= ...` |
| **What if error = measured − reference?** | Sign flipped → positive feedback → runaway. Disk above setpoint → error>0 → command>0 → motor forward → further from setpoint. | `p_controller.sv` line 19: `error = reference - measured` |

### **6. Motor Drive**
| Question | Answer | Code Reference |
|----------|--------|----------------|
| **How does `motor_drive` turn signed command into three L298N signals?** | `duty = \|command\|` (8 bits) → PWM `motor_en`. Direction: `motor_in1 = arm && (command>0)`, `motor_in2 = arm && (command<0)`. L298N: EN=PWM, IN3=forward, IN4=reverse. Coast when EN=0. | `motor_drive.sv` lines 7, 10, 16–17 |
| **What is coast mode?** | `motor_en=0` → L298N outputs high-Z → motor spins freely. Not braking (IN3=IN4=0 with EN=1). Used here: PWM off = coast. | `motor_drive.sv` header lines 18–24 |
| **PWM frequency and calculation?** | `PWM_TICK_PERIOD = 100M/(10k×255) = 39.2→39`. `pwm` counter: 255 steps. Actual: `100M/(39×255) = 10.06 kHz`. | `downcounter_subsystem.sv` line 5; `pwm.sv` line 5 |
| **What happens when sw[15] is down?** | `arm=0` → `pwm` enable=0 → `motor_en=0`. Direction regs: `arm && ... = 0`. All three outputs 0 → motor off. | `motor_drive.sv` lines 10, 16–17 |

### **7. Hardware / Wiring**
| Question | Answer |
|----------|--------|
| **Why 2.2 kΩ resistor in each encoder wire?** | Encoder outputs pull up to 5V. FPGA pins are 3.3V max. Resistor + clamp diodes limit current: `(5-3.3)/2200 ≈ 0.77 mA`. Without: 10s of mA → latch-up risk. |
| **Clamp diode current with/without resistor?** | Without: encoder drive strength (10s of mA). With 2.2k: ~0.77 mA per channel, safe. |
| **Why must all grounds be connected?** | Encoder, L298N, FPGA must share 0V reference. Without: signals float, noise, wrong logic levels. |
| **Which way up is pin 1 of a Pmod?** | Top-right when facing connector, key slot on left. Square pad on Basys3 = pin 1. JB1=ch_a, JB2=ch_b, JC1=IN3, JC2=IN4, JC3=ENB. |
| **Encoder 5V wire — where does it go?** | L298N "5V" screw terminal. **NOT** a Pmod pin. |
| **Motor runs away instead of holding?** | Turn motor off (sw[15] down), swap the two motor wires on L298N OUT3/OUT4. |

### **8. Design Structure**
| Question | Answer |
|----------|--------|
| **What is `disk_pkg` for? Single source of truth?** | All shared constants in one place: `CLK_FREQ_HZ`, `ENCODER_LINES`, `POSITION_WIDTH`, `COMMAND_MAX`, etc. Change once (e.g., encoder 512→500 lines), all modules update. No duplicate constants. |
| **Why these subsystem boundaries?** | `input_conditioning` (async→sync), `downcounter_subsystem` (timing), `quad_decoder` (measure), `setpoint_control` (reference), `p_controller` (control law), `motor_drive` (actuator), `display_subsystem` (human I/O). Each hides implementation, shows clean interface. |
| **What does a subsystem hide? What does it show?** | Hides: internal signals, parameter defaults, algorithm details. Shows: ports, parameters. Example: `p_controller` hides product width, limiting logic; shows `sample_tick`, `reference`, `measured`, `kp`, `p_action`. |
| **Why is `disk_top` structural only?** | No logic, only instantiations + wiring. All behavior in subsystems. Easy to read hierarchy, swap modules (e.g., replace `p_controller` with PI), testbench overrides parameters. |

### **9. Control Theory**
| Question | Answer |
|----------|--------|
| **Why oscillate at high Kp when textbook says never?** | Textbook = continuous time, no delay. Real: 100 Hz sample (10 ms delay), PWM quantization, motor inductance, friction nonlinearity, encoder quantization. Phase lag from delay + quantization → instability. |
| **What are Ku and Tu on your rig? How measured?** | Ku = ultimate gain (sustained oscillation), Tu = oscillation period. Increase Kp until continuous oscillation. Measure period on scope. Example: Ku≈7, Tu≈0.5s. |
| **Why stop short at low Kp?** | Static friction (stiction) > motor torque at low PWM duty. Near setpoint: `command = Kp×error` small → < stiction threshold. Integral action (E4) accumulates error → overcomes stiction. |
| **What would integral action change?** | Adds `Ki×∫error dt`. Eliminates steady-state error (stops *at* setpoint). But adds phase lag → can worsen oscillation if not tuned. E4: wrap `p_controller` + integrator + sum + final limit. |

### **10. Verification**
| Question | Answer |
|----------|--------|
| **What does `tb_disk_top` check? What does it NOT check?** | Checks: closed-loop step response, position tracks setpoint, no runaway, PWM/direction correct. Not: exact settling time (Kp/friction dependent), analog behavior (motor current, voltage drop). |
| **Which testbench catches a decoder counting backwards?** | `tb_quad_decoder`: feeds known A/B sequences (forward/backward), checks `position` increments/decrements correctly. `tb_disk_top` would also show wrong direction in closed loop. |
| **Why safety gate requires `tb_disk_top` pass before motor armed?** | Prevents running on hardware with broken logic. Verifies: encoder→position, buttons→setpoint, controller→command, motor_drive→PWM/direction all connected correctly. If passes, low risk of motor runaway. |

**Key:** Single source of truth. Change `ENCODER_LINES` once → everything updates.

### `synchronizer.sv`
```systemverilog
module synchronizer #(parameter int WIDTH = 1) (
    input  logic             clk,
    input  logic [WIDTH-1:0] d,
    output logic [WIDTH-1:0] q
);
    logic [WIDTH-1:0] meta;
    always_ff @(posedge clk) begin
        meta <= d;
        q    <= meta;
    end
endmodule
```
**Key lines 7–8:** Two-flop chain, `meta` never used except as input to second flop. **No reset** → can synchronize reset button itself.

### `synchronizer_subsystem.sv`
```systemverilog
module synchronizer_subsystem #(
    parameter int KP_WIDTH = 4
) (
    input  logic clk, reset_button, ch_a, ch_b,
    input  logic [KP_WIDTH-1:0] kp_switches,
    input  logic display_switch, arm_switch,
    output logic reset, encoder_a, encoder_b,
    output logic [KP_WIDTH-1:0] kp,
    output logic display, arm
);
    synchronizer #(.WIDTH(1)) RESET_SYNC    (.clk(clk), .d(reset_button), .q(reset));
    synchronizer #(.WIDTH(1)) ENCODER_A_SYNC(.clk(clk), .d(ch_a),           .q(encoder_a));
    synchronizer #(.WIDTH(1)) ENCODER_B_SYNC(.clk(clk), .d(ch_b),           .q(encoder_b));
    synchronizer #(.WIDTH(KP_WIDTH)) KP_SYNC (.clk(clk), .d(kp_switches),   .q(kp));
    synchronizer #(.WIDTH(1)) DISPLAY_SYNC  (.clk(clk), .d(display_switch), .q(display));
    synchronizer #(.WIDTH(1)) ARM_SYNC      (.clk(clk), .d(arm_switch),     .q(arm));
endmodule
```
**Key:** `RESET_SYNC` — reset button goes through synchronizer *without* a reset (intentional). `KP_WIDTH` (4) switches grouped into one instance.

### `debounce.sv`
```systemverilog
module debounce #(
    parameter int CLK_FREQ       = 100_000_000,
    parameter int STABLE_TIME_MS = 50
) (
    input  logic clk, reset, button,
    output logic result
);
    localparam int MS_PER_SECOND = 1000;
    localparam int MAX_COUNT   = (CLK_FREQ / MS_PER_SECOND) * STABLE_TIME_MS;
    localparam int COUNT_WIDTH = $clog2(MAX_COUNT + 1);
    localparam logic [COUNT_WIDTH-1:0] COUNT_LIMIT = COUNT_WIDTH'(MAX_COUNT);
    logic button_sync, button_previous, changed;
    logic [COUNT_WIDTH-1:0] count;
    synchronizer #(.WIDTH(1)) BUTTON_SYNCHRONIZER (.clk(clk), .d(button), .q(button_sync));
    always_ff @(posedge clk) button_previous <= button_sync;
    assign changed = (button_sync != button_previous);
    always_ff @(posedge clk) begin
        if (reset) begin
            count  <= '0;
            result <= 1'b0;
        end else if (changed) begin
            count <= '0;
        end else if (count < COUNT_LIMIT) begin
            count <= count + 1'b1;
        end else begin
            result <= button_sync;
        end
    end
endmodule
```
**Key line 10:** `CLK_FREQ / 1000` *first* → avoids 32-bit overflow (100M × 50 = 5B > 2³²).
**Key lines 24–28:** `changed` restarts counter on any edge. Only commits `result` after full stable period.

### `debounce_subsystem.sv`
```systemverilog
module debounce_subsystem #(
    parameter int CLK_FREQ = 100_000_000,
    parameter int DEBOUNCE_MS = 50
) (
    input  logic clk, reset, step_up_button, step_down_button,

    debounce #(.CLK_FREQ(CLK_FREQ), .STABLE_TIME_MS(DEBOUNCE_MS))
        STEP_DOWN_DEBOUNCE (.clk(clk), .reset(reset), .button(step_down_button), .result(step_down));
endmodule
```

### `downcounter.sv`
```systemverilog
module downcounter #(parameter int PERIOD = 1000) (
    input  logic clk, reset, enable,
    output logic zero
);
    localparam int COUNT_WIDTH = $clog2(PERIOD);
    localparam logic [COUNT_WIDTH-1:0] START_COUNT = COUNT_WIDTH'(PERIOD - 1);
    logic [COUNT_WIDTH-1:0] count;
    always_ff @(posedge clk) begin
        if (reset) begin
            count <= START_COUNT;
            zero  <= 1'b0;
        end else if (enable) begin
            if (count == 0) begin
                count <= START_COUNT;
                zero  <= 1'b1;
            end else begin
                count <= count - 1'b1;
                zero  <= 1'b0;
            end
        end else begin
            zero <= 1'b0;
        end
    end
endmodule
```
**Key line 5:** `COUNT_WIDTH = $clog2(PERIOD)` → holds `PERIOD-1` (e.g., 1M → 20 bits).
**Key line 14:** `zero` registered → glitch-free clock enable.

### `downcounter_subsystem.sv`
```systemverilog
module downcounter_subsystem #(
    parameter int CTRL_PERIOD     = 1_000_000,
    parameter int PWM_TICK_PERIOD = 39
) (
    input  logic clk, reset,
    output logic control_tick, pwm_tick
);
    downcounter #(.PERIOD(CTRL_PERIOD))     CONTROL_TICK_GEN (.clk(clk), .reset(reset), .enable(1'b1), .zero(control_tick));
    downcounter #(.PERIOD(PWM_TICK_PERIOD)) PWM_TICK_GEN     (.clk(clk), .reset(reset), .enable(1'b1), .zero(pwm_tick));
endmodule
```
**Key line 4:** `CTRL_PERIOD = 100M/100 = 1,000,000` → 100 Hz.
**Key line 5:** `PWM_TICK_PERIOD = 100M/(10k×255) = 39.2→39` → actual PWM = 10.06 kHz.

### `quad_decoder.sv`
```systemverilog
module quad_decoder #(
    parameter int POSITION_WIDTH = 16
) (
    input  logic                             clk, reset, a, b,
    output logic signed [POSITION_WIDTH-1:0] position
);
    logic [1:0] ab, ab_previous;
    assign ab = {a, b};
    always_ff @(posedge clk) ab_previous <= ab;
    always_ff @(posedge clk) begin
        if (reset) position <= '0;
        else begin
            case ({ab_previous, ab})
                4'b00_10, 4'b10_11, 4'b11_01, 4'b01_00: position <= position + 1'b1;
                4'b00_01, 4'b01_11, 4'b11_10, 4'b10_00: position <= position - 1'b1;
                default: position <= position;
            endcase
        end
    end
endmodule
```
**Key line 9:** `ab_previous` registered *without reset* → flushes in 1 cycle.
**Key lines 13–15:** All 8 legal transitions explicit. Illegal → ignored.

### `setpoint_control.sv`
```systemverilog
module setpoint_control #(
    parameter int POSITION_WIDTH = 16,
    parameter int SETPOINT_STEP  = 512
) (
    input  logic                             clk, reset, step_up, step_down,
    output logic signed [POSITION_WIDTH-1:0] setpoint
);
    localparam logic signed [POSITION_WIDTH-1:0] STEP_SIZE = POSITION_WIDTH'(SETPOINT_STEP);
    logic up_previous, down_previous, up_pressed, down_pressed;
    always_ff @(posedge clk) begin
        up_previous   <= step_up;
        down_previous <= step_down;
    end
    assign up_pressed   = step_up   && !up_previous;
    assign down_pressed = step_down && !down_previous;
    always_ff @(posedge clk) begin
        if (reset)          setpoint <= '0;
        else if (up_pressed)   setpoint <= setpoint + STEP_SIZE;
        else if (down_pressed) setpoint <= setpoint - STEP_SIZE;
    end
endmodule
```
**Key lines 11–12:** Rising-edge detection on debounced buttons (held high for millions of cycles). `up_pressed` priority if both same cycle.

### `p_controller.sv` — **CRITICAL MODULE**
```systemverilog
module p_controller #(
    parameter int IN_WIDTH  = 16,
    parameter int KP_WIDTH  = 4,
    parameter int FRAC_BITS = 0,
    parameter int OUT_WIDTH = IN_WIDTH + KP_WIDTH + 2,
    parameter int OUT_MAX   =  (2**(OUT_WIDTH - 1)) - 1,
    parameter int OUT_MIN   = -(2**(OUT_WIDTH - 1))
) (
    input  logic                        clk, reset, sample_tick,
    input  logic signed [IN_WIDTH-1:0]  reference, measured,
    input  logic        [KP_WIDTH-1:0]  kp,
    output logic signed [IN_WIDTH:0]    error,
    output logic signed [OUT_WIDTH-1:0] p_action
);
    localparam int PRODUCT_WIDTH = IN_WIDTH + 1 + KP_WIDTH + 1;
    localparam int CMP_WIDTH = (OUT_WIDTH > PRODUCT_WIDTH) ? OUT_WIDTH : PRODUCT_WIDTH;
    localparam logic signed [CMP_WIDTH-1:0] LIMIT_HIGH = CMP_WIDTH'(OUT_MAX);
    localparam logic signed [CMP_WIDTH-1:0] LIMIT_LOW  = CMP_WIDTH'(OUT_MIN);
    logic signed [PRODUCT_WIDTH-1:0] product, scaled;
    logic signed [CMP_WIDTH-1:0]     wide;
    assign error   = reference - measured;
    assign product = error * $signed({1'b0, kp});
    assign scaled  = product >>> FRAC_BITS;
    assign wide    = CMP_WIDTH'(scaled);
    always_ff @(posedge clk) begin
        if (reset) p_action <= '0;
        else if (sample_tick) begin
            if (wide > LIMIT_HIGH)      p_action <= OUT_WIDTH'(LIMIT_HIGH);
            else if (wide < LIMIT_LOW)  p_action <= OUT_WIDTH'(LIMIT_LOW);
            else                        p_action <= OUT_WIDTH'(wide);
        end
    end
endmodule
```
**Memorize:**
- Line 14: `PRODUCT_WIDTH = 22` — **full multiply width, no truncation**
- Line 19: `error = reference - measured` — 17 bits, **cannot overflow**
- Line 20: `$signed({1'b0, kp})` — **forces signed multiply**
- Line 21: `>>>` arithmetic shift — preserves sign
- Line 22: `CMP_WIDTH'(scaled)` — sign-extends before compare
- Lines 25–30: Limit at full width, **only truncate after confirming in range**

### `pwm.sv`
```systemverilog
module pwm #(parameter int WIDTH = 8) (
    input  logic             clk, reset, enable, count_enable,
    input  logic [WIDTH-1:0] duty_cycle,
    output logic             pwm_out
);
    localparam logic [WIDTH-1:0] MAX_CODE = '1;
    logic [WIDTH-1:0] counter;
    always_ff @(posedge clk) begin
        if (reset || !enable) counter <= '0;
        else if (count_enable) begin
            if (counter == MAX_CODE - 1) counter <= '0;
            else                         counter <= counter + 1'b1;
        end
    end
    always_ff @(posedge clk) begin
        if (reset) pwm_out <= 1'b0;
        else       pwm_out <= enable && (counter < duty_cycle);
    end
endmodule
```
**Key:** `MAX_CODE = 255`. Counter runs 0..254 (255 steps). Registered output → glitch-free.

### `motor_drive.sv`
```systemverilog
module motor_drive #(
    parameter int COMMAND_WIDTH = 9,
    parameter int DUTY_WIDTH    = 8
) (
    input  logic                            clk, reset, arm, pwm_tick,
    input  logic signed [COMMAND_WIDTH-1:0] command,
    output logic                            motor_en, motor_in1, motor_in2
);
    logic [DUTY_WIDTH-1:0] duty;
    assign duty = (command < 0) ? DUTY_WIDTH'(-command) : DUTY_WIDTH'(command);
    pwm #(.WIDTH(DUTY_WIDTH)) MOTOR_PWM (
        .clk(clk), .reset(reset), .enable(arm), .count_enable(pwm_tick),
        .duty_cycle(duty), .pwm_out(motor_en)
    );
    always_ff @(posedge clk) begin
        if (reset) begin
            motor_in1 <= 1'b0; motor_in2 <= 1'b0;
        end else begin
            motor_in1 <= arm && (command > 0);
            motor_in2 <= arm && (command < 0);
        end
    end
endmodule
```
**Key:** `arm=0` forces all three outputs to 0. Coast mode = PWM off.

module position_to_degrees #(

### `bin_to_bcd.sv` (Double-dabble)
```systemverilog
module bin_to_bcd (
    input  logic        clk, reset,
    input  logic [15:0] bin_in,
    output logic [15:0] bcd_out
);
    localparam logic [15:0] MAX_VALUE = 16'd9999;
    logic [15:0] binary, bcd, bcd_plus_3;
    logic [4:0]  shifts_left;
    logic        too_big;
    assign bcd_plus_3[3:0]   = (bcd[3:0]   >= 4'd5) ? bcd[3:0]   + 4'd3 : bcd[3:0];
    assign bcd_plus_3[7:4]   = (bcd[7:4]   >= 4'd5) ? bcd[7:4]   + 4'd3 : bcd[7:4];
    assign bcd_plus_3[11:8]  = (bcd[11:8]  >= 4'd5) ? bcd[11:8]  + 4'd3 : bcd[11:8];
    assign bcd_plus_3[15:12] = (bcd[15:12] >= 4'd5) ? bcd[15:12] + 4'd3 : bcd[15:12];
    always_ff @(posedge clk) begin
        if (reset) begin
            binary <= '0; bcd <= '0; shifts_left <= '0; too_big <= 1'b0; bcd_out <= '0;
        end else if (shifts_left == 0) begin
            binary      <= bin_in;
            bcd         <= '0;
            shifts_left <= 5'd16;
            too_big     <= (bin_in > MAX_VALUE);
        end else begin
            bcd         <= {bcd_plus_3[14:0], binary[15]};
            binary      <= {binary[14:0], 1'b0};
            shifts_left <= shifts_left - 1'b1;
            if (shifts_left == 1)
                bcd_out <= too_big ? 16'hEEEE : {bcd_plus_3[14:0], binary[15]};
        end
    end
endmodule
```
**Key lines 13–16:** "Add 3 if ≥5" per digit. **Line 28:** 16 shifts @ 1 bit/cycle → 170 ns/conversion. `too_big` → displays `EEEE` for >9999.

### `seven_segment_digit_selector.sv`
```systemverilog
module seven_segment_digit_selector (
    input  logic clk, reset,
    output logic [3:0] digit_select,
    output logic [3:0] an_outputs
);
    localparam int COUNTER_WIDTH = 17;
    logic [COUNTER_WIDTH-1:0] count;
    logic [1:0] digit_index;
    always_ff @(posedge clk) begin
        if (reset) begin count <= '0; digit_index <= '0; end
        else begin
            count <= count + 1'b1;
            if (count == '1) digit_index <= digit_index + 1'b1;
        end
    end
    assign digit_select = 4'b0001 << digit_index;
    assign an_outputs   = ~digit_select;
endmodule
```
**Key:** 17-bit counter → 763 Hz/digit → 191 Hz refresh. `count == '1` (all ones) → next digit.

## Key Concepts & "Why" Explanations

### Single Clock Domain Design
- All flops clocked by `clk` (100 MHz). `control_tick`, `pwm_tick` are **clock enables** (1-cycle pulses).
- **Why?** No CDC, single STA run, no metastability between clocks, simpler floorplanning.

### Synchronous Reset Everywhere
- Every `always_ff` has `if (reset) ...` (active high).
- `reset` comes from `synchronizer_subsystem` → `RESET_SYNC` → synchronized `reset_button`.
- **Why?** Predictable, synthesizable, no async reset removal issues.

### Metastability Hardening
| Signal | Protection |
|--------|------------|
| `reset_button` | 2-FF synchronizer (no reset on synchronizer) |
| `ch_a`, `ch_b` | 2-FF synchronizer in `synchronizer_subsystem` |
| `kp_switches`, `display_switch`, `arm_switch` | 2-FF synchronizer |
| `step_up_button`, `step_down_button` | Synchronizer **inside** `debounce` → then debounced |

### Parameterized Reuse (The `p_controller` Pattern)
- **No `import disk_pkg`** in reusable modules.
- All sizes, limits, scaling are **parameters**.
- `disk_top` passes project-specific values.
- **Result:** Same `p_controller` used in PI controller (E4), boost converter, etc.

### Arithmetic Safety Rules
1. **Error width = operand width + 1** (prevents overflow on subtraction)
2. **Multiply at full width** (never truncate before multiply)
3. **Compare at full width** (only truncate after confirming in range)
4. **`$signed({1'b0, unsigned})`** for signed × unsigned multiply
5. **`>>>`** for arithmetic right shift (preserves sign)

### Two's Complement Modulo Trick
```systemverilog
count_in_rev = position[REV_BITS-1:0];  // modulo 2^N
```
Works because `COUNTS_PER_REV = 2048 = 2^11`. For negative: `-512 = 0xFE00`, low 11 bits = `1536 = 2048 - 512`.

### PWM Design
- Counter: `0 .. 254` (255 steps)
- `duty_cycle = 255` → always on (100%)
- `duty_cycle = 0` → always off (0%)
- `count_enable` sets frequency: `PWM_freq = count_enable_rate / 255`
- Registered output → glitch-free
